# Cashflow reads three published views through a read-only role

Cashflow (`cashflow-bp`) stops taking MercadoPago and Stripe cobros typed by hand into its Excel and reads them from here. It connects to this database as `cashflow_reader`, a role that can SELECT three views and nothing else: `basket_v_cashflow_credits` (what each Provider made available, by day: Stripe payouts by arrival date, MercadoPago releases by `MONEY_RELEASE_DATE` in Argentina time), `basket_v_cashflow_fx` (the daily rates it converts EUR payouts with) and `basket_v_cashflow_freshness` (when each feed last brought data, so cashflow can refuse stale numbers). The views run with their owner's rights, so the role holds no grant on any table and cannot reach Subscriber names or emails. The views are a contract: columns may be added, but a rename or retype ships together with cashflow's adapter. Rules that are cashflow's decisions stay in cashflow: the bank value date (+1 business day), the bank's commission, the weekly averaging of rates.

Rejected: an HTTP endpoint, because this app has no read token, both databases share a host, and cashflow already reads the Portal's catalog the same way; granting SELECT on the mirror tables, because that hands cashflow `basket_payments` and couples it to our internal schema; and computing the cash view in cashflow from raw movements, because how a Provider's ledger becomes "money available on a day" is knowledge about the Provider, which lives here.
