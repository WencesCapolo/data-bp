# Identity and authorization come from the portal's Auth DB

This app does not log anyone in. It embeds Better Auth as a Session reader against the shared `basket_auth` database (same `BETTER_AUTH_SECRET`, cookie domain `.basket-app.com`), sends unauthenticated visitors to `portal.basket-app.com/login`, and admits a session only if it holds an Acceso row for `analytics` in `auth_app_access`; otherwise it redirects to the portal's `/no-access`. The Nivel of that row is the role: `admin` → admin, `read` and `write` → viewer, and every dashboard admits both. The Google client, the `/api/auth` route, the `auth_allowed_emails` allowlist, its `/admin` manager page and the `@basquetpass.tv` domain check previously kept here are gone. Auth config is three values: the shared secret, the Auth DB URL and the portal origin. Rationale and rejected alternatives: portal repo, `docs/adr/0009-central-acceso-single-auth-server.md`.
